# IconForge 2.1.0

IconForge 2.1 adds one opt-in default directory for the two places an icon library is most useful: forge output and
bulk apply. It also documents and verifies exact matching for separately installed Chrome channels.

## One default icon directory

Save, inspect, or remove the preference with the new `config` command:

```bash
iconforge config set default-directory "$HOME/app-icons"
iconforge config get default-directory
iconforge config unset default-directory
```

After it is set, forge writes there when `-o/--output` is omitted, and bulk apply can omit its directory:

```bash
iconforge forge ./discord.png discord
iconforge apply --all --dry-run --verbose
```

An explicit forge output or bulk directory always wins for that invocation. Without a saved preference, forge keeps its
current-directory fallback and bulk apply still requires a directory. Bare `iconforge apply` remains a usage error and
never begins an implicit scan.

The preference is stored as structured data in `~/.config/iconforge/config.plist`, or below an absolute
`$XDG_CONFIG_HOME`. Relative inputs are saved as canonical absolute paths. IconForge does not source shell
configuration, rejects malformed or unsafe preference files, and preserves the preference during uninstall.

## Separate Chrome channel icons

When Stable and Dev are both installed, these exact filenames independently target their full application names:

```text
google-chrome.icns      -> Google Chrome.app
google-chrome-dev.icns  -> Google Chrome Dev.app
```

The shorter `chrome.icns` and `chrome-dev.icns` stems also match their respective bundle names. Do not keep
`chrome.icns` beside `google-chrome.icns`: both target Stable Chrome, so IconForge deliberately stops at bulk preflight
instead of choosing one.

## Upgrade

```bash
brew update
brew upgrade villagealchemist/iconforge/iconforge
iconforge config set default-directory "$HOME/app-icons"
```

See the [complete 2.1.0 command reference](https://github.com/villagealchemist/iconforge/blob/v2.1.0/docs/USAGE.md)
for precedence, configuration safety, matching, and exit-status details.
