# IconForge 2.2.0

Make it at the forge. Keep it at the hearth. IconForge 2.2 adds separate defaults for generated artwork and finished
icons, then lets you apply a matching icon by application name.

## Configure once, apply by name

```bash
iconforge config set the-forge "$HOME/icon-work"
iconforge config set the-hearth "$HOME/app-icons"
iconforge config show
iconforge forge ./firefox.png Firefox
iconforge apply Firefox --dry-run
iconforge apply Firefox
```

Put an application-named file such as `Firefox.icns` in the hearth before applying it. The two directories may be the
same or different, and existing ICNS files need no import. Direct lookup uses the selected application's filename,
display name, and bundle name. Multiple matching icons or duplicate app installations require an explicit selection.

Use explicit paths for a different library, icon, or application installation:

```bash
iconforge apply Firefox --from "$HOME/alternate-icons" --dry-run
iconforge apply Firefox --icon ./experimental.icns --dry-run
iconforge apply Firefox --app-root "/Volumes/Tools/Applications" --dry-run
iconforge apply "/Volumes/Tools/Applications/Firefox.app" --dry-run
iconforge apply --all --dry-run --verbose
```

Bulk application still requires an explicit bulk flag. Bare apply remains a usage error.

## Compatibility and configuration

Existing `default-directory` preferences remain the fallback for either new setting until that setting is configured.
Explicit output, icon, and library paths take precedence without changing saved preferences. There is no automatic
migration write. Config updates preserve other keys, reject malformed documents, and use locked atomic replacement.

```bash
iconforge config show
iconforge config path
iconforge config get the-hearth
iconforge config unset the-forge
```

Unsetting a new setting can reveal the legacy fallback again. Image-first invocation, explicit icon application,
existing exit codes, native application, and the explicit internal-ICNS strategy remain supported.

## Diagnostics, refresh, and completion

```bash
iconforge doctor
iconforge doctor Finder
iconforge capabilities
iconforge completion bash
iconforge completion zsh
iconforge completion fish
```

Doctor is read-only. Completion scripts are printed for you to load in your shell. Long value options also accept
equals syntax. Repeatable application-root options add locations for one invocation; CoreServices is now included
among the default macOS discovery roots.

```bash
iconforge forge ./firefox.png --output="$HOME/icon-work"
iconforge apply Firefox nuke --dry-run
iconforge apply Firefox --refresh --dry-run
iconforge refresh --dry-run
```

Refresh and nuke invoke the same existing current-user cache operation. Cache work stays opt-in and runs once after a
successful bulk apply. Finding a system-managed application does not make it writable or enable special Finder Dock
customization.

## Upgrade

```bash
brew update
brew upgrade villagealchemist/iconforge/iconforge
iconforge --version
iconforge config show
```

This is a source-only release. Homebrew builds the vendored Go processor and the AppKit helper from the exact release
commit. The release adds no external runtime dependency. macOS remains the only implemented application backend.

See the [2.2.0 CLI guide](https://github.com/villagealchemist/iconforge/blob/v2.2.0/docs/CLI.md) and
