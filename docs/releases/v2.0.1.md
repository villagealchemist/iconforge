# Icon Forge 2.0.1

Icon Forge 2.0.1 is a corrective release for application-icon application and ICNS completeness.

## Native application icons by default

Automatic application icon changes now use the bundled AppKit helper whenever it is available. The icon is stored as
a Finder-level custom icon instead of replacing files inside the application bundle. This preserves the application's
contents and signature and avoids the macOS presentation plate observed when apps such as Visual Studio Code were
changed internally.

`--strategy internal-icns` remains available as an explicit expert option. The compatibility name `fileicon` still
means `native`; Icon Forge does not require or execute a third-party `fileicon` program.

## Complete ICNS output

Forged files now contain all ten standard and Retina ICNS representations. The seven unique pixel sizes remain 16,
32, 64, 128, 256, 512, and 1024 pixels, with shared PNG data used for equivalent standard and Retina representations.
The output round-trips through macOS `iconutil` as a complete ten-file iconset.

## Restoring legacy state

If an app has both an old `*_ugly.icns` backup and a Finder custom icon, `restore` now restores the internal backup and
removes the Finder icon in the same run. Native apply warns when it finds a legacy internal backup.

If Icon Forge 2.0.0 internally modified a vendor application, reinstall that application from its trusted source
before applying the icon again with 2.0.1. Restoring the original icon bytes cannot reconstruct the vendor's original
code signature.

## Updating

After the v2.0.1 source release and Homebrew formula are published:

```bash
brew update
brew upgrade villagealchemist/iconforge/iconforge
iconforge --version
```

Application updates may still remove Finder custom-icon data. Icon Forge can reapply or remove that data, but it cannot
make an application's updater preserve it.
