# Changelog

All notable user-facing changes to IconForge are recorded here.

## 2.2.0

### Configuration and application lookup

- Added independent `the-forge` output and `the-hearth` ICNS-library preferences. Existing `default-directory`
  settings remain a fallback, and explicit command-line paths take precedence.
- Added `config show` for effective directories and their sources, and `config path` for the preference-file location.
  Updates preserve unrelated keys, use atomic replacement and an exclusive lock, and reject malformed preferences.
- Added direct application-by-name icon lookup from the hearth, with explicit `--icon` and `--from` overrides.
  Ambiguous applications or matching icons require an explicit selection rather than choosing by scan order.
- Added repeatable `--app-root` search locations and included macOS CoreServices in the default discovery roots.

### Command line and documentation

- Added long value options in `--name=value` form, `apply <app> nuke`, the `refresh` command alias, and
  `--refresh` aliases on apply and restore. Bulk operations still require `--all`.
- Added read-only `doctor` and `capabilities` commands and generated Bash, Zsh, and Fish completion scripts.
  Verified Zsh configuration action/key completion and aligned discovery and refresh help with the new commands.
- Introduced a built-in macOS backend boundary while retaining the existing image processor, native helper,
  transactional operations, and explicit-only `internal-icns` strategy.
- Published the forge/hearth CLI guide and architecture notes, retaining the v2.1.0 execution-engine reference.
- Extended Homebrew verification for independent preferences and the installed 2.2.0 command surface.

## 2.1.0

### Configuration

- Added `iconforge config set|get|unset default-directory` for one optional, structured user preference shared by forge
  output and bulk apply. Relative values are saved as stable absolute paths, explicit command-line directories take
  precedence, and shell configuration is never sourced.
- Forge now uses the configured directory when `-o/--output` is omitted, falling back to the current directory when the
  preference is unset.
- Bulk `apply -a/--all` now accepts an omitted directory when a default is configured. Without either an explicit or
  configured directory, it retains the existing usage error.

### Applications

- Documented exact channel-specific bulk names such as `google-chrome.icns` and `google-chrome-dev.icns`, allowing
  separately installed Chrome channels to receive distinct icons without alias collisions.

## 2.0.0

IconForge 2 is a stateless macOS icon workflow: forge complete ICNS files, inspect app icon metadata, apply icons
natively or through an explicit expert strategy, restore supported changes, and reset current-user icon caches.

### Forge

- Added first-class `forge` and image-first invocation for PNG, JPEG, WebP, TIFF, and GIF artwork.
- Added multi-image and explicit recursive input with preserved relative paths, spaces, and Unicode filenames.
- Added all ten standard and Retina ICNS representations, generated by IconForge's Go image processor.
- Added deterministic preflight, case-insensitive destination-collision detection, aggregate overwrite confirmation,
  `-f/--force`, low-resolution warnings, and full dry-run analysis.
- Added private staging, atomic output replacement, and publication rollback so a failed batch does not intentionally
  leave a partial output tree.

### Applications

- Added read-only `inspect` with bundle icon metadata, loose-icon discovery, and asset-catalog classification.
- Added shared path/name resolution across the current directory, user applications, system applications, and nested
  application directories, including one-run confirmation for a unique partial match.
- Added native Finder custom-icon apply through the bundled Objective-C/AppKit helper. Native is the default and the
  only bulk strategy; it leaves application contents and signatures unchanged.
- Added explicit direct-only `internal-icns` for writable loose-icon bundles, with first-original backup, mandatory ad
  hoc signing, strict verification, and automatic rollback.
- Added restore for Finder custom icons and one unambiguous internal backup.
- Added explicit bulk apply for recursively discovered `.icns` files, complete preflight, deterministic application,
  unresolved-entry summaries, and exactly-once optional Nuke.
- Added `nuke` for current-user icon caches, including dry-run and optional app touching. It refuses root execution.

### Command line

- Added paired short and long spellings for every public option and an end-of-options marker on every command.
- Root `-v/--version` and command-local `apply -v/--verbose` are selected by argument position.
- No arguments prints root help; directory scans and application discovery never begin implicitly.
- Inputs, outputs, applications, and bulk icon directories are supplied on each invocation rather than remembered.

### Distribution and verification

- Added user-local source installation and a source-building Homebrew formula pinned to an exact release commit.
- Bundled and vendored the imported `golang.org/x/image` packages with complete third-party notices for offline,
  reproducible builds.
- Added Intel and Apple-silicon CI, Go and shell test suites, strict signature checks, native-helper tests, installer and
  formula contract tests, and a temporary cross-compilation check.
